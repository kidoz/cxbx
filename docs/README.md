# CXBX documentation

Choose a starting point based on what you need to do. These docs follow
[Diátaxis](https://diataxis.fr/): lessons, task guides, technical reference,
and explanations each have their own place.

| Your need | Section | First page |
|---|---|---|
| Learn through a guided exercise | [Tutorials](tutorials/README.md) | [Explore a conformance probe](tutorials/explore-conformance.md) |
| Build, launch, test, or diagnose something | [How-to guides](how-to/README.md) | [Build CXBX](how-to/build.md) |
| Look up settings, formats, contracts, or recorded results | [Reference](reference/README.md) | [Launcher reference](reference/launcher.md) |
| Understand architecture and design decisions | [Explanation](explanation/README.md) | [Launcher architecture](explanation/launcher.md) |

New contributors can begin with [Explore a conformance probe](tutorials/explore-conformance.md),
then [build CXBX](how-to/build.md). For title bring-up, start with
[Collect and narrow down a title failure](how-to/debug-title.md).

For a graphics regression, [capture an NV2A frame](how-to/capture-nv2a.md),
[compare the baseline and candidate](how-to/compare-nv2a-captures.md), and
[inspect offline state and pixels](how-to/inspect-nv2a-capture.md).
The [capture reference](reference/nv2a-capture.md) defines the format and replay
contracts; [title-debugging design](explanation/title-debugging.md) explains
why the evidence is collected.
